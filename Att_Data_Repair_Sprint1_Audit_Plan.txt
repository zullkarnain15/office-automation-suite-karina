1. Ringkasan Eksekutif

Att Data Repair dapat ditambahkan tanpa merombak modul lama, dengan syarat dibuat sebagai subfitur Utilities baru yang berdiri sendiri dan hanya melakukan reuse pada utilitas umum yang stabil. Risiko keseluruhan: sedang.

Rekomendasi arsitektur utama: buat package baru utilities/att_data_repair/, reader khusus untuk report Attachment Consolidation, engine repair terpisah, TXT writer khusus naming Att Data Repair, report writer streaming openpyxl, dan integrasi Unified UI lewat adapter/service seperti Attachment Consolidation.

Sprint 1 selesai sebagai audit saja. Tidak ada implementasi fitur, tidak ada build EXE, dan tidak ada commit.

8. Proposed Processing Pipeline

1. Preflight:
   cek file .xlsx, read-only, cek sheet Valid_Records dan Invalid_Records, cek header wajib.
2. Resolve config:
   global/local period dan output, TXT_Max_Rows, defaults time, generate flags.
3. Read:
   baca semua row kedua sheet, simpan Source_File, Source_Sheet, Source_Row, Relative_Path, Raw_Value.
4. Normalize:
   NIK, workflow, date, time, status source.
5. Validate:
   NIK, date dalam periode, workflow HO/Branch.
6. Repair:
   align Date_Out, normalize separator jam, swap time, default time, min duration 61 menit.
7. Classify:
   Final_Records, Changed_Records, Anomaly, Change_Log.
8. Split workflow:
   HO dan Branch dipisah; duplikat NIK+tanggal tidak di-merge.
9. Export TXT:
   max 10.000 rows/file; format HRIS 6 kolom quoted.
10. Export report:
   satu workbook audit.
11. History/logging:
   Process.log, summary.json, job_history, job_files, job_status_events.

12. Proposed Test Strategy

Minimal:
- Unit tests parser reader Valid_Records/Invalid_Records.
- Date tests: Excel date cell, text date, ambiguous date, outside period.
- Time tests: 7;20, 7.20, invalid, Excel time.
- Repair rule tests: align Date_Out, swap in/out, default day, min 61 menit, no night shift.
- Duplicate record tests: NIK+tanggal sama tetap semua diproses.
- Workflow tests: HO, Branch, invalid/empty.
- TXT tests: HRIS format, split 10.000, 4 digit shared code, duplicate filename prevention.
- Report tests: sheet order, changed/anomaly/change log linkage.
- Configuration tests: template, import/export, old workbook compatibility.
- Regression tests: Attachment Consolidation existing report dan TXT naming tetap tidak berubah.

13. Risiko dan Mitigasi

Rendah:
- Reuse openpyxl, no dependency baru.
- Format HRIS TXT sudah jelas.

Sedang:
- Menambah feature ketiga akan memecahkan tests yang saat ini assert exactly two active features.
  Mitigasi: update kontrak tests sesuai fitur baru.
- Sheet config baru berkonflik dengan exact SHEET_ORDER.
  Mitigasi: template current exact, importer tolerant untuk workbook lama.
- TXT naming baru berbeda dari writer existing.
  Mitigasi: writer khusus Att Data Repair.

Tinggi:
- Migration SQLite v3 menyentuh bootstrap/validator/import/export.
  Mitigasi: migration backup-first, tests schema/migration/roundtrip.
- Parsing tanggal teks ambigu.
  Mitigasi: gunakan periode sebagai guard, anomaly bila tidak pasti.

14. Ambiguitas atau Konflik yang Ditemukan

1. Struktur folder requirement konseptual Att_Data_Repair/YYYY-MM-DD_XX berbeda dari pola existing Utilities/<Feature>/<Workflow>/<YYYY-MM>/<timestamp>.
   Rekomendasi: user perlu memutuskan apakah Att Data Repair boleh memakai pola existing atau harus memakai konsep baru.

2. Existing TXT suffix random 3 digit berbeda per file; requirement Att Data Repair minta 4 digit sama untuk seluruh job.
   Rekomendasi: writer khusus.

3. Existing Attachment Consolidation workflow di engine/report memakai HO dan Branch; database/UI sebagian memakai BRANCH.
   Rekomendasi: engine/output report gunakan Branch, UI/database boleh normalize internal.

4. Existing Unified UI browse Utilities adalah folder picker; Att Data Repair butuh file picker.
   Rekomendasi: branching UI per feature.

5. Attachment Consolidation tidak punya ENGINE_VERSION; Reconciliation punya ENGINE_VERSION = 1.0.0.
   Rekomendasi: Att Data Repair punya version constant sendiri.
