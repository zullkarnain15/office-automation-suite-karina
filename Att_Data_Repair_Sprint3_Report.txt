11. TXT NAMING

Pola:
Att_Data_Repair_[Workflow]-[NNN]_[RRRR].txt

Contoh HO:
Att_Data_Repair_HO-001_4837.txt

Contoh Branch:
Att_Data_Repair_Branch-001_4837.txt

Arti NNN:
- Nomor pecahan file per workflow.
- Minimum 3 digit.
- Mulai dari 001 untuk masing-masing workflow.
- Jika lebih dari 999, format tetap bertambah tanpa overwrite, misalnya 1000.

Arti RRRR:
- Kode unik 4 digit per job.
- Range 1000 sampai 9999.
- Sama untuk semua file TXT dalam job yang sama.

12. UNIQUE CODE

Generator:
- Default menggunakan secrets.SystemRandom().randint(1000, 9999).
- Test menggunakan injected CodeProvider agar deterministik.

Range:
- TXT_UNIQUE_CODE_MIN = 1000.
- TXT_UNIQUE_CODE_MAX = 9999.
- Kode di luar range menghasilkan UniqueCodeCollisionError.

Retry:
- retry_limit default 100.
- Seluruh filename diplan dulu untuk satu kode.
- Jika satu target filename sudah ada, kode baru di-generate dan semua filename diplan ulang.

Collision handling:
- Existing final file tidak dioverwrite.
- Test collision membuat Att_Data_Repair_HO-001_4837.txt lebih dulu, provider memberi 4837 lalu 5837, hasil akhir memakai 5837.
- Test retry exhaustion menghasilkan UniqueCodeCollisionError.

16. JOB STATUS LOGIC

SUCCESS:
- Ada FinalRecords.
- Tidak ada anomaly.
- Seluruh artifact wajib berhasil dibuat.

PARTIAL_SUCCESS:
- Ada FinalRecords.
- Ada satu atau lebih anomaly.
- FinalRecords valid tetap diekspor ke TXT.

NO_VALID_RECORDS:
- Tidak ada FinalRecords.
- Job folder, TXT folder, Report folder, Process.log, dan summary.json tetap dibuat.
- Tidak membuat TXT kosong.
- Anomaly tetap dihitung.

FAILED:
- Terjadi error setelah job folder dibuat pada output pipeline.
- Process.log mencatat ERROR.
- summary.json status FAILED diusahakan tetap ditulis.
- Result mengisi error_message dengan type dan message aman.

17. ERROR HANDLING

Atomic write:
- TXT ditulis ke file temporary di folder target lalu rename ke final.
- summary.json ditulis ke summary.json.tmp lalu replace.

Temporary cleanup:
- TXT temporary dihapus saat failure.
- summary temporary dihapus saat failure.
- Test memverifikasi tidak ada temporary TXT dan summary.json.tmp tertinggal setelah sukses.

Existing file protection:
- File final existing tidak dioverwrite.
- Collision filename menyebabkan regenerate unique code.
- Jika semua retry collision, UniqueCodeCollisionError dilempar.

Behavior failure setelah job folder dibuat:
- run_job mengembalikan AttDataRepairJobResult status FAILED.
- Process.log tetap ada bila filesystem memungkinkan.
- Failed summary ditulis dengan error type/message.
- Job folder tidak dihapus otomatis karena log diperlukan untuk diagnosis.

Fatal preflight sebelum job folder:
- validate_request, output root validation, dan workbook read dilakukan sebelum reserve job folder.
- Fatal source error dapat raise exception tanpa membuat folder kosong.
