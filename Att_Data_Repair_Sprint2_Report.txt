4. Penjelasan Model Data

Model Sprint 2 dibuat dengan dataclass dan contract eksplisit:

- AttDataRepairRequest
  Request in-memory untuk analisis. Memuat source_report, period_start, period_end, minimum_duration_minutes, dan default waktu harian.

- SourceRecord
  Row mentah dari Valid_Records atau Invalid_Records. Menjaga lineage minimal: source_workbook, source_sheet, source_file, relative_path, source_row, source_record_no, source_status, source_reason, dan raw_value.

- TimeParseMetadata
  Metadata parsing waktu: value, original_value, normalized, dan reason.

- NormalizedRecord
  Hasil normalisasi sebelum repair rules. Menyimpan workflow, nik, date_in, time_in, date_out, time_out, parsing_flags, invalid_codes, dan raw source.

- RepairChange
  Audit perubahan per field: record_id, field_name, original_value, final_value, change_code, reason.

- RepairAnomaly
  Record yang tidak masuk final: record_id, anomaly_code, reason, action, source lineage.

- FinalRecord
  Record final in-memory yang layak untuk Sprint berikutnya: workflow, NIK, date/time final, duration_minutes, source lineage, final_status, changes.

- AttDataRepairAnalysisResult
  Hasil analisis lengkap: final_records, changed_records, anomalies, change_log, source_counts, status_counts.

Exception khusus:
- AttDataRepairError
- RequestValidationError
- SourceWorkbookError
- MissingRequiredSheetError
- MissingRequiredColumnError

5. Penjelasan Reader dan Preflight

Reader berada di:
- utilities/att_data_repair/report_reader.py

Reader menggunakan openpyxl read-only:
- load_workbook(..., read_only=True, data_only=True, keep_links=False)

Reader selalu menutup workbook dan tidak melakukan save atau mutation.

Kontrak source:
- Sheet wajib Valid_Records
- Sheet wajib Invalid_Records

Header matching:
- trim whitespace
- case-insensitive
- underscore/whitespace tolerant
- tidak memakai fuzzy matching berlebihan

Fatal preflight:
- Missing Valid_Records -> MissingRequiredSheetError
- Missing Invalid_Records -> MissingRequiredSheetError
- Missing required header -> MissingRequiredColumnError
- Source bukan .xlsx atau tidak dapat dibaca -> SourceWorkbookError / RequestValidationError

Reader mengabaikan row kosong sepenuhnya, menjaga urutan record sumber, dan tidak menggabungkan duplikat.

6. Urutan Repair Rules

Pipeline engine:

1. validate request
2. reader preflight dan read source workbook
3. normalize SourceRecord menjadi NormalizedRecord
4. apply repair rules
5. classify final/anomaly/changed/change log
6. return AttDataRepairAnalysisResult in-memory

Urutan rule per record:

1. Workflow invalid:
   anomaly INVALID_WORKFLOW, stop record.

2. NIK invalid:
   anomaly INVALID_NIK, stop record.

3. Date_In invalid:
   anomaly INVALID_DATE, stop record.

4. Date_In di luar periode:
   anomaly OUTSIDE_REPORT_PERIOD, stop record.

5. Date_Out:
   final Date_Out selalu mengikuti Date_In.
   Jika berbeda atau invalid, catat DATE_OUT_ALIGNED_TO_DATE_IN.

6. Time format:
   Jika format jam diperbaiki, catat TIME_FORMAT_NORMALIZED.

7. Kedua jam valid:
   Jika Time_In > Time_Out, tukar dan catat TIME_IN_OUT_SWAPPED.
   Jika durasi kurang dari minimum, pertahankan Time_In dan sesuaikan Time_Out.
   Jika hasil melewati 23:59, gunakan default hari.

8. Hanya Time_In valid:
   Pertahankan Time_In.
   Isi Time_Out dari default out hari atau minimum duration.
   Jika melewati 23:59, gunakan default hari.

9. Hanya Time_Out valid:
   Pertahankan Time_Out.
   Isi Time_In dari default in hari atau Time_Out - minimum duration.
   Jika kurang dari 00:00 atau tidak logis, gunakan default hari.

10. Kedua jam invalid:
    Gunakan default hari.

11. Minggu:
    Jika kedua jam valid dan durasi valid, pertahankan.
    Jika jam invalid, gunakan default Minggu 09:30-12:05.

12. Duplikat NIK + tanggal:
    Tidak merge, tidak deduplicate, semua record diproses mandiri.

13. Semua perubahan menghasilkan RepairChange.

14. Record masuk FinalRecord hanya jika workflow, NIK, tanggal, waktu final, urutan waktu, dan durasi minimum valid.
